# 轻听 LightListen · v0.3.3

轻听是使用 QQ 音乐**官方网页**作为登录与歌曲来源的精简 Android 播放器。主界面采用原生控件，提供搜索、我的喜欢、我的歌单、播放队列和底部播放控制；由用户在内嵌的官方网页登录，不复制 Chrome 登录状态，不保存账号密码。

v0.3.3 修复分段播放在网络与缓存之间切换时的版本判断，以及下载未完成时过早淘汰旧音频的问题。新包：[LightListen-0.3.3-debug.apk](outputs/2026-10-14-v0.3.3-review-fixes/final-02/LightListen-0.3.3-debug.apk)。所有应用页面固定竖屏。历史版本安装包和原始证据继续保留；各版本实测范围见下方记录。

正常播放时，允许缓存的音频自动保存在应用私有目录。只有覆盖完整文件才显示完整。网页登录、歌曲授权仍联网，已缓存的同版本音频优先本地复用；后台播放由 Android 播放服务承担。

## 使用

1. 打开轻听，从顶部“更多”选择“登录 QQ 音乐”，在官方网页完成登录，再返回原生主界面。
2. 输入歌曲名搜索，或打开“我的喜欢”“我的歌单”。歌单行显示名称及来源提供的首数；未提供数量时不猜测。
3. 点选歌曲开始播放，并将当前列表作为本地播放队列。底部可以暂停、切换上一首 / 下一首和拖动进度；“播放队列”可选曲或移除条目。切到后台后由播放服务继续播放。
4. 从“更多”打开“缓存管理”，查看已保存音频、本次歌曲下载、缓存读取和版本校验。再次播放相同版本时优先读取已有缓存；空间不足会淘汰旧音频。清理音频前会确认，清理会停止播放，但保留登录和播放队列。
5. 保持联网使用。新播放链接先做很小的版本校验；确认相同音频后复用本机文件，不重新保存整首。内容或音质变了、服务器未提供可靠版本信息时仍需下载。

搜索与歌单的数量范围：

- 搜索固定每页 30 首，最多读取 3 页、90 首，并明确显示官网报告的总数；可通过更精确关键词缩小范围。已实测 90 条搜索及空结果提示，不将当前展示结果当作全部搜索结果。
- “我的喜欢”和所选歌单通过官网接口分页读取，每页最多 100 首，本版最多读取 1,000 首。只有确认所有歌曲读取完毕才提示完整；达到上限、分页失败或返回数量不符时，明确提示“尚未读取完整”及已读取数量，不将网页默认的前 10 首当作全量。
- 歌曲可用性与播放权限以当前登录账号和官方网页返回结果为准。歌单目录能完整读取，并不代表每首歌曲都已播放或完整缓存。

原有网页缓存实验入口保留。“严格离线”仅作额外实验，会同时阻止网页认证，可能无法刷新或切歌；它只限制本 App，不修改手机 Wi-Fi 或移动数据。“恢复联网”回到默认模式，日常原生播放不以严格离线为前提。

缓存列表与数字只表示本 App 自己确认写入的音频，不把网页加载条当作完整性证据。缓存身份使用哈希，不保存完整签名链接。新链接只有通过当前服务器授权与版本校验才可引用已有文件；严格离线时，未覆盖的片段明确报告缺失，不自动联网补齐。加密或受许可保护、无法被系统 WebView 正常播放的内容不会被破解。

跨链接复用要求同来源、同资源路径和同音质；仅剔除已知的 `guid/vkey/uin/fromtag` 参数，其他查询参数保留。新链接的 `bytes=0-0` 请求必须成功返回真实 206，且强 ETag、总长度和音频类型与完整缓存相同，缓存策略也允许复用。403、验证失败或未知链接的严格离线请求都不能借用别的缓存。链接映射绑定具体音频版本，不另存一份歌曲。校验正文通常只有 1 字节，但认证、请求头、网页本身仍有网络流量。

正常已提交音频控制在 256 MiB 以内，单个资源上限 64 MiB。下载中的临时响应另设全局 64 MiB 上限，所有并发响应共同预留该空间；音频字节在提交交接期间最多占 320 MiB，另有少量元数据。只有新响应完整接收且元数据保存成功后，才优先淘汰过期音频，再按元数据最近保存时间淘汰最旧音频；读取缓存不会更新这一顺序。截断、取消或元数据发布失败不会因容量淘汰损失其它旧音频。当前正在追加的资源受保护，无法安排容量或临时预算不足时只跳过该响应的缓存。若发布后删除旧文件失败，已发布的新响应保留，未删旧字节仍计入占用，暂时可能超出 256 MiB 目标；此时停止接纳新缓存或发布其它在途响应，后续请求重试清理，故障解除后自动恢复。总音频字节仍受上述暂存峰值约束。

跨响应合并需要相同的强 ETag；没有可靠文件版本标识时只保留最近一个完整响应片段，不能拼成“完整歌曲”。原生播放器通过代理内部传递的版本哈希核对网络与缓存，既不会把同版本缓存误判成变化，也不允许已缓存的旧片段接上新版本网络字节。原始 ETag 不落盘，磁盘格式不变；无强 ETag 的旧完整缓存仍可读取，但不能与网络或被替换的缓存文件混合。单次响应覆盖整份资源仍可确认字节完整。完整缓存不等于已实际离线播放通过。

保留的 WebView 缓存实验对响应采取严格校验：网页请求分段而服务器忽略 Range、返回 200 时，显示请求失败（502），不猜测区间；缺失明确长度或资源总长度超出 WebView 流接口的整数范围时也拒绝。普通 QQ 音乐实测的 206 分段适用。自建缓存只接管 `*.stream.qqmusic.qq.com` 的普通音频，不能保证其他来源可缓存。

## 数据

- 登录与网站数据由系统 WebView 保存在本应用私有空间；不与 Chrome 共用。
- 自建音频缓存在 `files/audio-cache/`，不导出歌曲或凭证。
- 音频缓存与网页登录数据分开；清理音频缓存不会退出账号。
- 原生播放队列保存在本机，只包含歌曲标识、标题、歌手、专辑、时长及播放位置等信息，不保存签名播放链接或登录凭据。
- v0.1.x 的旧缓存保留。只有旧完整 URL 哈希被精确命中时才补齐资源身份，不能猜测旧文件归属；无法精确识别的旧缓存不能自动跨链接复用。
- `no-store` 不落盘；需要重新验证的内容不作为可离线复用缓存。没有明确缓存期限的普通音频使用实验性的 24 小时默认期限；服务端明确期限优先。
- 本版无云服务、无分析 SDK，不申请文件、联系人、相机或麦克风权限。Android 备份关闭。
- 含账号头像和昵称的登录页验证截图仅保留在本机，不纳入 Git；对应的方向验证结果仍记录在验收 JSON 中。

## 构建与验证

Java 17，Gradle 8.10.2，Android Gradle Plugin 8.7.3，compileSdk/targetSdk 36，minSdk 26。使用本项目独立 Wrapper：

```powershell
.\gradlew.bat assembleDebug lintDebug
```

配置本机 `JAVA_HOME` / `ANDROID_HOME` 或忽略的 `local.properties`。输出 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。新构建必须单独保存 APK 哈希和设备证据。

设备自测使用独立 WebView 配置和独立缓存目录，测试自产音频的 Range 请求、缺段拒绝、缓存完整度与重启后离线复用。**这些测试不等于 QQ 音乐登录后实播通过**；真实歌曲结果须单独记录。

自测使用单独的 `:cachetest` 进程，由该进程在报告后自行退出；正常登录页不参与测试重启。调试入口仅在 debug 构建存在。断网验证会关闭本机测试音服务器，并核对原生音频网络字节为 0。
